# Politique explicite plutôt qu'implicite — et une seule voix.
#
# Ce fichier n'est pas le seul servi sous /robots.txt : Cloudflare insère
# en tête un bloc managé (« BEGIN Cloudflare Managed content ») qui déclare
# un Content-Signal `search=yes,ai-train=no,use=reference` puis interdit
# nommément une trentaine de robots d'entraînement — Google-Extended,
# GPTBot, ClaudeBot, CCBot, Applebot-Extended, Amazonbot, Diffbot,
# cohere-ai, meta-externalagent et d'autres. C'est une réserve de droits
# volontaire sur les contenus de l'agence (textes, photographies), au titre
# de l'article 4 de la directive 2019/790.
#
# Ce choix étant assumé, ce fichier ne le contredit pas : il n'autorise
# plus aucun des robots que le bloc managé interdit. Un robots.txt qui dit
# à la fois « Disallow: / » et « Allow: / » pour un même agent est pire que
# l'un ou l'autre : chaque robot tranche à sa façon, et la consigne devient
# illisible. Ne pas réintroduire ici un Allow pour un agent bloqué en amont
# sans lever d'abord le blocage côté Cloudflare (AI Crawl Control).
#
# Restent nommés ci-dessous les robots qui FONT CITER le site dans les
# réponses génératives sans l'absorber pour entraîner un modèle. Ce sont
# ceux qui comptent pour la visibilité, et ils ne sont pas bloqués.
#
# Rien n'est interdit ici qui ne le soit déjà pour des raisons de fond :
# l'administration et les API. Le reste du site est ouvert.

# ---------------------------------------------------------------------
# Règle générale
# ---------------------------------------------------------------------
User-agent: *
Allow: /
Disallow: /admin/
Disallow: /api/
#
# /espace/ (espace membre) n'est PAS bloqué ici, bien qu'il n'ait rien à
# faire dans un index. La page est déjà en `noindex` — et les deux
# directives se contredisent : un robot qui ne peut pas la charger ne peut
# pas y lire le `noindex`, et Google range alors ce genre d'URL en
# « indexée malgré le blocage par robots.txt », URL nue dans les
# résultats. Comme /espace/ est liée depuis /talent/ et la politique de
# confidentialité, le robot y arrivera : il faut donc qu'il puisse lire la
# consigne. `noindex` seul est la règle la plus forte des deux.
#
# Les URL paramétrées (/contact?profile=…, /brief/?from=…) ne sont PAS
# bloquées ici, bien qu'elles soient des doublons de leur page canonique.
# Les bloquer paraissait propre et aurait été une faute : /brief/ n'est
# jamais liée autrement qu'avec un paramètre — un Disallow l'aurait coupée
# de tout lien interne. La balise <link rel="canonical">, présente sur
# chaque page et pointant l'URL sans paramètre, est l'outil juste pour
# cela : elle regroupe les variantes au lieu de les rendre invisibles.

# ---------------------------------------------------------------------
# Recherche générative et assistants — autorisés nommément.
#
# Deux familles, utiles l'une comme l'autre :
#   · les robots qui PARCOURENT le site pour l'indexer et le citer en
#     réponse (OAI-SearchBot, PerplexityBot, Claude-SearchBot…) ;
#   · ceux qui récupèrent une page à la demande d'un utilisateur qui l'a
#     mentionnée (ChatGPT-User, Perplexity-User, Claude-User).
# Le premier groupe fait entrer le site dans les réponses, le second le
# rend consultable en conversation. Aucun des deux n'alimente
# l'entraînement d'un modèle : ils lisent pour répondre et citer.
# ---------------------------------------------------------------------
